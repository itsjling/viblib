## Findings considered and rejected

- **Extract Fallow's two duplicate blocks now**: rejected. Each block appears
  only twice, and a shared helper would hide command-specific rules before it
  removes meaningful maintenance cost.
- **Make three internal exports private as a standalone change**: rejected as a
  separate plan. `getCatalogPath`, `getSyncDrift`, and `upstreamLockPath` are
  used within their own modules; remove their export modifiers when those files
  next change and tests confirm no intended external API.
- **Bound captured subprocess output immediately**: rejected for this plan set.
  The CLI buffers list/discovery output, but the personal-catalog scale and
  pinned child process make this lower leverage than the nine selected items.
- **Batch very large install/uninstall argument lists**: rejected for now. A
  personal catalog is unlikely to approach operating-system argument limits,
  and batching would add partial-failure policy that the current product does
  not need yet.
- **Upgrade every dependency with a newer major**: rejected. The production
  audit is clean; version availability alone does not justify migration risk.
- **Clear all existing lint warnings in one change**: rejected. The warning set
  mixes style and complexity. Plans 004 and 005 address risky complexity with
  tests; a future warning ratchet should be a separate policy decision.
